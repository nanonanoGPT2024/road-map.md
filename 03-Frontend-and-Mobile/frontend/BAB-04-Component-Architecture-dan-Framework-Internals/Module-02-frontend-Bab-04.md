### 3. Concept & Internal Architecture (Mendalam)

#### 3.1 VDOM Reconciliation vs. Reactive Proxy vs. Compile-time Invalidation
Framework frontend modern terbagi ke dalam tiga paradigma internal utama dalam memetakan perubahan state ke Document Object Model (DOM):

```
                        ┌──────────────────────────────────────────────────────────┐
                        │                   State Mutation Event                   │
                        └────────────────────────────┬─────────────────────────────┘
                                                     │
         ┌───────────────────────────────────────────┼────────────────────────────────────────┐
         │ (Paradigma 1: VDOM Tree Diff)             │ (Paradigma 2: Fine-Grained Reactive)   │ (Paradigma 3: Compile-Time)
         ▼                                           ▼                                        ▼
┌──────────────────┐                       ┌──────────────────┐                     ┌──────────────────┐
│ Virtual DOM Tree │                       │ Proxy Trap (Set) │                     │ Direct DOM Call  │
└────────┬─────────┘                       └────────┬─────────┘                     └────────┬─────────┘
         │ (Render pass creates new VNode)          │ (Notifies exact Subscriber)            │ (Generated by compiler)
         ▼                                          ▼                                        ▼
┌──────────────────┐                       ┌──────────────────┐                     ┌──────────────────┐
│ Tree Diff / Fiber│                       │ Targeted Effect  │                     │ el.data = value  │
│ Priority Scheduler                       │ Re-execution     │                     │ (Zero Diff Loop) │
└────────┬─────────┘                       └────────┬─────────┘                     └──────────────────┘
         │ (Compute patch delta)                    │ (No Tree Traversal)
         ▼                                          ▼
┌──────────────────────────────────────────────────────────────┐
│                    Host DOM Node Mutation                    │
└──────────────────────────────────────────────────────────────┘
```

1. **Virtual DOM Reconciliation (React Fiber Engine)**:
   - React memisahkan proses rekonsiliasi menjadi dua fase: **Render Phase** (asynchronous, interruptible via Fiber work-loop) dan **Commit Phase** (synchronous, uninterruptible DOM writes).
   - Struktur Fiber adalah sebuah linked-list dua arah dengan referensi `child`, `sibling`, dan `return` (parent). Setiap node menyimpan `memoizedState`, `lanes` (prioritas pembaruan), dan `alternate` (pointer ke *work-in-progress* atau *current* fiber).
   - Mekanisme **Double Buffering**: React membuat pohon kedua (`workInProgress`) yang mencerminkan status masa depan layar. Setelah pekerjaan selesai tanpa interupsi prioritas tinggi, React mengalihkan pointer root ke pohon baru dalam satu operasi atomic.

2. **Fine-Grained Reactivity (Vue 3 / SolidJS Runtime)**:
   - Memanfaatkan ECMAScript `Proxy` handler (`get`, `set`).
   - Saat properti dibaca saat eksekusi komputasi atau render, *dependency tracking* (`track()`) menambahkan efek aktif (`ActiveEffect`) ke dalam struktur data `WeakMap<Target, Map<Key, Set<Effect>>>`.
   - Ketika properti dimutasi, `trigger()` dijalankan untuk mengambil semua efek yang bergantung pada key tersebut dan mengeksekusinya secara langsung atau memasukkannya ke dalam scheduler queue. Tidak ada algoritma VDOM tree-diff global yang dijalankan (SolidJS bahkan tidak memiliki VDOM; Vue 3 menggunakan *hybrid patch flags*).

3. **Compile-Time Reactive Invalidation (Svelte Runtime)**:
   - Tidak ada virtual DOM runtime maupun proxy graph dependency memory overhead.
   - Kompiler mem-parsing kode komponen menjadi AST, menganalisis deklarasi variabel reaktif, dan menyisipkan fungsi penanda bitwise atau dirty-checking lokal (`$$invalidate`).
   - Operasi mutasi langsung diterjemahkan ke serangkaian instruksi imperatif manipulasi DOM native yang dibundel dalam blok fragment update.

#### 3.2 Fiber Scheduling & Priority Lanes Architecture
React Fiber mengklasifikasikan pembaruan menggunakan skema *31-bit Lane Priority*:
- **SyncLane**: Mutasi akibat user interaction langsung (klik, ketikan keyboard).
- **InputContinuousLane**: Transisi berkesinambungan (hover, drag, scrolling).
- **DefaultLane**: Pembaruan data asinkronus (fetch API response).
- **IdleLane / OffscreenLane**: Background pre-rendering atau offscreen computation.

Engine menjalankan algoritma Work Loop berbasis time-slicing:
```typescript
function workLoopConcurrent() {
  // Melakukan traversal Fiber linked-list selama browser frame masih memiliki alokasi waktu
  while (workInProgress !== null && !shouldYieldToHost()) {
    performUnitOfWork(workInProgress);
  }
}
```

Jika thread utama browser kehabisan frame budget (biasanya ~5ms untuk frame-deadline React Scheduler), scheduler menghentikan eksekusi sementara (*yields execution*), mengizinkan browser memproses event input atau paint, lalu melanjutkan unit of work berikutnya melalui API `MessageChannel`.

### 4. Why & What

| Dimensi | Pola Monolitik Konvensional | Compound / Headless Enterprise Pattern |
| :--- | :--- | :--- |
| **Kopling Logika & Tampilan** | Kuat (Tight Coupling); markup, styling, dan state bersatu dalam satu file monolitik. | Terputus total (Decoupled); logika diatur oleh headless engine/custom hook, markup bebas dikontrol konsumen. |
| **Fleksibilitas Desain** | Rendah; memerlukan puluhan props boolean (`hasIcon`, `isOutlined`, `sizeLarge`) yang menyebabkan "Prop Drilling Hell". | Sangat Tinggi; komponen disusun secara modular melalui sub-komponen deklaratif berorientasi relasi slot. |
| **Maintenance Cost** | Eksponensial seiring bertambahnya variasi edge case pada design system multi-aplikasi. | Linear dan terisolasi; fungsionalitas inti teruji pada layer headless tanpa terpengaruh perubahan stylesheet. |
| **Performa Rendering** | Rentan; perubahan satu state lokal me-render ulang seluruh sub-tree raksasa. | Optimal; pemisahan context atomik memastikan hanya node sub-tree terkecil yang dievaluasi ulang oleh scheduler. |

#### Problem Statement Enterprise
Pada aplikasi monolitik enterprise dengan ratusan pengembang, penambahan variasi komponen UI (seperti Dynamic Select, Data Grid, Wizard Form) menggunakan pendekatan passing props monolitik (`<Select data={...} isSearchable isMulti hasSelectAll renderCustomItem={...} />`) memicu kerapuhan (*fragility*), ledakan cyclomatic complexity, dan degradasi performa karena kegagalan garbage collection dari anonymous functions yang di-pass berulang kali.

Solusi: **Compound Headless Components** yang didorong oleh *Internal Finite State Machine (FSM)* dan *Context Boundary Injection*.

---

### 5. How (Workflow Detail)

Alur kerja arsitektur komponen compound tingkat lanjut:

1. **State Machine Initialization**:
   - Komponen Root menginisialisasi state engine (misal: Finite State Machine) melalui custom reducer.
2. **Context Provider Layering**:
   - Membagi context menjadi dua channel untuk menghindari re-render cascade:
     - `StateContext`: Menyimpan state terkomputasi (hanya di-subscribe oleh komponen yang menampilkan data).
     - `DispatchContext`: Menyimpan referensi metode aksi stabil (`useCallback` dengan dependency kosong) untuk interaksi user.
3. **Implicit Slot Linking**:
   - Sub-komponen (Compound children) mengonsumsi context secara selektif.
   - Menggunakan dynamic type-checking untuk memastikan sub-komponen dieksekusi hanya di dalam lingkup parent context yang valid (Inversion of Control).
4. **DOM Synchronization & Keyboard Navigation Protocol**:
   - Menghubungkan custom focus management dengan WAI-ARIA authoring practices melalui roving tabindex atau `aria-activedescendant`.
   - Mengikat event listener global (ESC key, Outside Click) pada `document` level dengan proper cleanup protocol saat unmount.

### 7. Simple Example & Practical Example

#### Simple Example: Native Compound Component Pattern dengan Isolated Context
Contoh minimal pemisahan State dan Dispatch channel untuk mereduksi cascade re-renders.

```tsx
// SimpleCompound.tsx
import React, { createContext, useContext, useState, useMemo, useCallback } from 'react';

type ToggleState = boolean;
type ToggleDispatch = () => void;

const ToggleStateContext = createContext<ToggleState | undefined>(undefined);
const ToggleDispatchContext = createContext<ToggleDispatch | undefined>(undefined);

export function Toggle({ children, defaultOn = false }: { children: React.ReactNode; defaultOn?: boolean }) {
  const [on, setOn] = useState<ToggleState>(defaultOn);
  const toggle = useCallback(() => setOn((prev) => !prev), []);

  return (
    <ToggleDispatchContext.Provider value={toggle}>
      <ToggleStateContext.Provider value={on}>
        <div className="toggle-container">{children}</div>
      </ToggleStateContext.Provider>
    </ToggleDispatchContext.Provider>
  );
}

export function ToggleButton() {
  const toggle = useContext(ToggleDispatchContext);
  if (!toggle) throw new Error('ToggleButton must be used within <Toggle>');
  
  return <button onClick={toggle}>Toggle Action</button>;
}

export function ToggleDisplay() {
  const on = useContext(ToggleStateContext);
  if (on === undefined) throw new Error('ToggleDisplay must be used within <Toggle>');

  return <span>State: {on ? 'ACTIVE' : 'INACTIVE'}</span>;
}
```

#### Practical Example: Enterprise-Grade Accessible Autocomplete / DataCombobox Engine
Implementasi komponen compound berstandar produksi yang memadukan Headless State Machine, WAI-ARIA 1.2 compliance, keyboard roving index, dynamic context routing, dan virtual list interface.

```tsx
// ComboboxEngine.tsx
import React, {
  createContext,
  useContext,
  useReducer,
  useCallback,
  useRef,
  useEffect,
  useId,
  ReactNode,
  KeyboardEvent,
  ChangeEvent,
} from 'react';

// ==========================================
// 1. STATE MACHINE TYPES & REDUCER
// ==========================================
export interface ComboboxOptionItem {
  id: string;
  label: string;
  value: string;
  disabled?: boolean;
}

interface ComboboxState {
  isOpen: boolean;
  query: string;
  highlightedIndex: number;
  selectedItem: ComboboxOptionItem | null;
  filteredItems: ComboboxOptionItem[];
}

type ComboboxAction =
  | { type: 'OPEN_MENU' }
  | { type: 'CLOSE_MENU' }
  | { type: 'SET_QUERY'; payload: string }
  | { type: 'NAVIGATE'; payload: 'UP' | 'DOWN' }
  | { type: 'SELECT_ITEM'; payload: ComboboxOptionItem }
  | { type: 'SET_HIGHLIGHTED'; payload: number }
  | { type: 'RESET' };

function comboboxReducer(state: ComboboxState, action: ComboboxAction): ComboboxState {
  switch (action.type) {
    case 'OPEN_MENU':
      return { ...state, isOpen: true };
    case 'CLOSE_MENU':
      return { ...state, isOpen: false, highlightedIndex: -1 };
    case 'SET_QUERY':
      return {
        ...state,
        query: action.payload,
        isOpen: true,
        highlightedIndex: state.filteredItems.length > 0 ? 0 : -1,
      };
    case 'NAVIGATE': {
      if (!state.isOpen || state.filteredItems.length === 0) {
        return { ...state, isOpen: true, highlightedIndex: 0 };
      }
      const count = state.filteredItems.length;
      let nextIndex = state.highlightedIndex;
      if (action.payload === 'DOWN') {
        nextIndex = (state.highlightedIndex + 1) % count;
      } else {
        nextIndex = (state.highlightedIndex - 1 + count) % count;
      }
      return { ...state, highlightedIndex: nextIndex };
    }
    case 'SELECT_ITEM':
      return {
        ...state,
        selectedItem: action.payload,
        query: action.payload.label,
        isOpen: false,
        highlightedIndex: -1,
      };
    case 'SET_HIGHLIGHTED':
      return { ...state, highlightedIndex: action.payload };
    case 'RESET':
      return {
        isOpen: false,
        query: '',
        highlightedIndex: -1,
        selectedItem: null,
        filteredItems: [],
      };
    default:
      return state;
  }
}

// ==========================================
// 2. SPLIT CONTEXT ARCHITECTURE
// ==========================================
interface ComboboxDispatchAPI {
  open: () => void;
  close: () => void;
  setQuery: (q: string) => void;
  navigate: (dir: 'UP' | 'DOWN') => void;
  select: (item: ComboboxOptionItem) => void;
  setHighlighted: (idx: number) => void;
  registerItems: (items: ComboboxOptionItem[]) => void;
}

const ComboboxStateContext = createContext<ComboboxState | null>(null);
const ComboboxDispatchContext = createContext<ComboboxDispatchAPI | null>(null);
const ComboboxIdContext = createContext<{ inputId: string; listboxId: string } | null>(null);

// ==========================================
// 3. ROOT COMPOUND COMPONENT
// ==========================================
interface ComboboxRootProps {
  children: ReactNode;
  items: ComboboxOptionItem[];
  onSelect?: (item: ComboboxOptionItem | null) => void;
  filterFn?: (items: ComboboxOptionItem[], query: string) => ComboboxOptionItem[];
}

export function ComboboxRoot({
  children,
  items,
  onSelect,
  filterFn = (opts, q) => opts.filter((o) => o.label.toLowerCase().includes(q.toLowerCase())),
}: ComboboxRootProps) {
  const inputId = useId();
  const listboxId = useId();

  const [state, dispatch] = useReducer(comboboxReducer, {
    isOpen: false,
    query: '',
    highlightedIndex: -1,
    selectedItem: null,
    filteredItems: items,
  });

  const stateRef = useRef(state);
  stateRef.current = state;

  // Filter synchronous execution during state derivation
  const activeFiltered = useMemo(() => {
    return filterFn(items, state.query);
  }, [items, state.query, filterFn]);

  // Sync derived filter to internal state
  useEffect(() => {
    state.filteredItems = activeFiltered;
  }, [activeFiltered]);

  const open = useCallback(() => dispatch({ type: 'OPEN_MENU' }), []);
  const close = useCallback(() => dispatch({ type: 'CLOSE_MENU' }), []);
  const setQuery = useCallback((q: string) => dispatch({ type: 'SET_QUERY', payload: q }), []);
  const navigate = useCallback((dir: 'UP' | 'DOWN') => dispatch({ type: 'NAVIGATE', payload: dir }), []);
  const setHighlighted = useCallback((idx: number) => dispatch({ type: 'SET_HIGHLIGHTED', payload: idx }), []);
  
  const select = useCallback(
    (item: ComboboxOptionItem) => {
      dispatch({ type: 'SELECT_ITEM', payload: item });
      onSelect?.(item);
    },
    [onSelect]
  );

  const registerItems = useCallback((_newItems: ComboboxOptionItem[]) => {
    // Dynamic registry hook-point if loaded asynchronously
  }, []);

  const api = useMemo<ComboboxDispatchAPI>(
    () => ({
      open,
      close,
      setQuery,
      navigate,
      select,
      setHighlighted,
      registerItems,
    }),
    [open, close, setQuery, navigate, select, setHighlighted, registerItems]
  );

  const ids = useMemo(() => ({ inputId, listboxId }), [inputId, listboxId]);

  return (
    <ComboboxIdContext.Provider value={ids}>
      <ComboboxDispatchContext.Provider value={api}>
        <ComboboxStateContext.Provider value={{ ...state, filteredItems: activeFiltered }}>
          <div className="relative inline-block w-full">{children}</div>
        </ComboboxStateContext.Provider>
      </ComboboxDispatchContext.Provider>
    </ComboboxIdContext.Provider>
  );
}

// ==========================================
// 4. COMPOUND SUB-COMPONENTS
// ==========================================
export function ComboboxInput({ placeholder }: { placeholder?: string }) {
  const state = useContext(ComboboxStateContext);
  const dispatch = useContext(ComboboxDispatchContext);
  const ids = useContext(ComboboxIdContext);

  if (!state || !dispatch || !ids) {
    throw new Error('ComboboxInput must be wrapped inside ComboboxRoot');
  }

  const handleKeyDown = (e: KeyboardEvent<HTMLInputElement>) => {
    switch (e.key) {
      case 'ArrowDown':
        e.preventDefault();
        dispatch.navigate('DOWN');
        break;
      case 'ArrowUp':
        e.preventDefault();
        dispatch.navigate('UP');
        break;
      case 'Enter':
        e.preventDefault();
        if (state.isOpen && state.highlightedIndex >= 0) {
          const targetItem = state.filteredItems[state.highlightedIndex];
          if (targetItem && !targetItem.disabled) {
            dispatch.select(targetItem);
          }
        }
        break;
      case 'Escape':
        e.preventDefault();
        dispatch.close();
        break;
      default:
        break;
    }
  };

  return (
    <input
      id={ids.inputId}
      type="text"
      role="combobox"
      aria-expanded={state.isOpen}
      aria-controls={ids.listboxId}
      aria-autocomplete="list"
      aria-activedescendant={
        state.highlightedIndex >= 0 ? `${ids.listboxId}-opt-${state.highlightedIndex}` : undefined
      }
      className="w-full px-4 py-2 border rounded-md focus:outline-none focus:ring-2 focus:ring-blue-500"
      placeholder={placeholder}
      value={state.query}
      onChange={(e: ChangeEvent<HTMLInputElement>) => dispatch.setQuery(e.target.value)}
      onFocus={() => dispatch.open()}
      onKeyDown={handleKeyDown}
    />
  );
}

export function ComboboxList({ children }: { children: (items: ComboboxOptionItem[]) => ReactNode }) {
  const state = useContext(ComboboxStateContext);
  const ids = useContext(ComboboxIdContext);

  if (!state || !ids) throw new Error('ComboboxList must be wrapped inside ComboboxRoot');
  if (!state.isOpen) return null;

  return (
    <ul
      id={ids.listboxId}
      role="listbox"
      aria-labelledby={ids.inputId}
      tabIndex={-1}
      className="absolute z-50 w-full mt-1 bg-white border border-gray-200 rounded-md shadow-lg max-h-60 overflow-auto"
    >
      {state.filteredItems.length === 0 ? (
        <li className="px-4 py-2 text-sm text-gray-400">Tidak ada data ditemukan</li>
      ) : (
        children(state.filteredItems)
      )}
    </ul>
  );
}

export function ComboboxOption({ item, index }: { item: ComboboxOptionItem; index: number }) {
  const state = useContext(ComboboxStateContext);
  const dispatch = useContext(ComboboxDispatchContext);
  const ids = useContext(ComboboxIdContext);

  if (!state || !dispatch || !ids) throw new Error('ComboboxOption must be wrapped inside ComboboxRoot');

  const isHighlighted = state.highlightedIndex === index;
  const isSelected = state.selectedItem?.id === item.id;

  return (
    <li
      id={`${ids.listboxId}-opt-${index}`}
      role="option"
      aria-selected={isSelected}
      aria-disabled={item.disabled}
      className={`px-4 py-2 cursor-pointer text-sm transition-colors ${
        item.disabled
          ? 'text-gray-300 cursor-not-allowed'
          : isHighlighted
          ? 'bg-blue-100 text-blue-900 font-medium'
          : 'text-gray-700 hover:bg-gray-50'
      } ${isSelected ? 'font-bold text-blue-600' : ''}`}
      onMouseEnter={() => !item.disabled && dispatch.setHighlighted(index)}
      onClick={() => !item.disabled && dispatch.select(item)}
    >
      {item.label}
    </li>
  );
}
```

### 8. Real World Case Study (Enterprise Scale)

#### Konteks: Trading Terminal Dashboard (FinTech Enterprise)
- **Problem Statement**: Modul eksekusi order pada broker institusional menampilkan Order Book live dan Security Selector. Data feed via WebSocket mentransmisikan perubahan harga 60 kali per detik (60 FPS). Implementasi awal menggunakan pustaka UI off-the-shelf berbasis un-memoized React Context. Hasilnya, ketikan pencarian simbol saham mengalami input latency hingga 450ms (*Long Task warning* di DevTools), CPU thread terkunci pada 100%, dan frame rate anjlok hingga < 12 FPS (*frame dropping*).
- **Akar Masalah**:
  1. *Context Blown Re-rendering*: Setiap tick harga memicu update root context. Karena data harga dan event handling berada dalam satu context, seluruh input field dan dropdown item di-render ulang secara rekursif.
  2. *Fiber Scheduling Starvation*: Render tree sinkronus berukuran 4,000 node menghalangi browser menjalankan painting pipeline.
- **Solusi Arsitektural**:
  1. **Dual-Context Separation Engine**: Memisahkan High-Frequency Mutable Store (menggunakan referensi mutable eksternal yang di-subscribe dengan `useSyncExternalStore`) dari Low-Frequency User Input State.
  2. **Concurrent React Transition API**: Membungkus pencarian simbol ke dalam `startTransition`, memetakan eksekusi search parsing ke `DefaultLane` / `TransitionLane`, membiarkan typing input tetap berjalan pada `SyncLane`.
  3. **Headless Virtualized Viewport**: Mengisolasi 10,000 baris order book ke dalam window virtualisasi DOM native, di mana mutasi DOM langsung dilakukan via direct node updating untuk critical numbers tanpa melalui Virtual DOM diffing.
- **Hasil Metrik Produksi**:
  - Input Latency (INP): Anjlok dari 450ms menjadi **14ms** (kategori Good/Hijau).
  - TBT (Total Blocking Time): Terpangkas dari 1,820ms menjadi **45ms**.
  - CPU Utilization: Rata-rata menurun dari 98% menjadi **18%** pada continuous stress load.

### 9. Trade-offs

```
                       ARSITEKTUR KOMPONEN
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
┌───────────────────────────────┐   ┌───────────────────────────────┐
│     Compound / Headless       │   │     Props-Driven Monolith     │
└──────────────┬────────────────┘   └──────────────┬────────────────┘
               │                                   │
  [+] Extensibilitas Markup            [+] Time-to-Market Rendah Awal
  [+] Minimalisasi Re-render           [+] API Kontrak Tersentralisasi
  [+] Isolasi State FSM Logic          [+] Mudah Diterapkan Junior Dev
  [-] Boilerplate Awal Tinggi          [-] Prop Explosion / Rigid Code
  [-] Learning Curve Kompleks          [-] Re-render Cascade Tinggi
  [-] Abstraksi Fragmentasi DOM        [-] Maintenance Sulit saat Scale
```

| Varian Arsitektur | Dampak Latensi Eksekusi | Kompleksitas Skalabilitas Tim | Memory Consumption (Heap) |
| :--- | :--- | :--- | :--- |
| **Monolithic Prop-Driven** | Buruk; tree traversal memicu GC pauses akibat regenerasi props object inline. | Rendah di awal, namun memburuk secara eksponensial setelah melewati 5 variasi bisnis. | Rendah; struktur data flat tanpa dependency injection layer. |
| **Compound Headless (Split Context)** | Sangat Baik; patch update terisolasi pada leaf node yang bergantung secara granular. | Sangat Baik; Tim UI/UX dapat mengubah styling/DOM tanpa menyentuh core testing state. | Moderat; overhead memori kecil untuk instance Context Provider dan Reducer registry. |
| **Fine-Grained Compiler-Driven (Svelte/Solid)** | Mendekati Native DOM speed; bypass overhead komputasi Fiber reconciler. | Baik; penulisan ringkas, namun interoperabilitas antar platform (Micro-Frontend) membutuhkan runtime wrapper. | Sangat Rendah; tidak ada representasi Virtual Tree yang disimpan di memori heap client. |

### 10. Common Mistakes & Troubleshooting

#### 10.1 Passing Object Literal Langsung ke Context Provider Value
- **Kesalahan**: Menulis `<ComboboxContext.Provider value={{ state, dispatch }}>`. Setiap parent komponen di-render, object literal baru dialokasikan di memory heap, menghasilkan referensi memori baru, yang secara instan memaksa **semua** consumer komponen me-render ulang dirinya sendiri, merusak optimasi `React.memo`.
- **Solusi**: Bungkus value dengan `useMemo`:
  ```tsx
  const contextValue = useMemo(() => ({ state, dispatch }), [state, dispatch]);
  ```

#### 10.2 Memory Leak: Uncleaned Observer & Global DOM Listener
- **Kesalahan**: Mengaitkan listener `keydown` atau `IntersectionObserver` di dalam lifecycle komponen tanpa fungsi disposal pada cleanup phase `useEffect`.
  ```tsx
  // SALAH
  useEffect(() => {
    window.addEventListener('resize', handleResize);
  }, []); // Missing return () => window.removeEventListener('resize', handleResize);
  ```
- **Deteksi & Solusi**: Gunakan Chrome DevTools **Memory Tab** -> Buat *Allocation Profiler Snapshot*. Cari instance `Detached HTMLDivElement` yang retained by closures. Pastikan semua subscription selalu mengembalikan cleanup closure.

#### 10.3 Inversion of Control Crash: Penggunaan Sub-komponen Di Luar Scope
- **Kesalahan**: Developer konsumen memanggil `<ComboboxOption />` tanpa membungkusnya di dalam `<ComboboxRoot />`. Muncul TypeError: `Cannot read properties of null (reading 'highlightedIndex')`.
- **Solusi**: Fail-fast assertion guard pada custom hook reader:
  ```typescript
  function useComboboxContext() {
    const ctx = useContext(ComboboxStateContext);
    if (!ctx) {
      throw new Error(
        '[CRITICAL INVARIANT]: Hook/Komponen Combobox.* tidak dapat dirender di luar context <ComboboxRoot>!'
      );
    }
    return ctx;
  }
  ```

### 11. Best Practices (Production Checklist)

- [ ] **Context Segregation**: Pisahkan State (yang sering berubah) dari Action Dispatcher API (fungsi-fungsi manipulasi stabil).
- [ ] **Component Invariant Assertion**: Berikan pesan error eksplisit yang menghentikan execution crash jika child component dipanggil tanpa parent provider.
- [ ] **WAI-ARIA Pattern Compliance**: Terapkan atribut ARIA standar (`role`, `aria-expanded`, `aria-activedescendant`, `aria-controls`, `aria-disabled`).
- [ ] **Roving Tabindex Architecture**: Hindari meletakkan `tabIndex={0}` pada ratusan item list; kelola satu pointer navigasi keyboard menggunakan `aria-activedescendant` atau dynamically managed index focus.
- [ ] **Pure Subtree Isolation**: Lapisi consumer komponen individual dengan `React.memo` yang menggunakan customized comparison callback jika prop mapping bersifat non-primitive.
- [ ] **Synthetic Event Batching Alignment**: Hindari pembacaan DOM sinkronus (`offsetWidth`, `getBoundingClientRect`) tepat setelah memicu mutasi state untuk menghindari *Layout Thrashing / Reflow Waterfall*.
- [ ] **Strict Explicit Interfaces**: Hindari passing broad interfaces seperti `props: any` atau `Record<string, unknown>`. Definisikan strict contract generic `<TItem, TValue>`.

#### Langkah 2: Implementasi Headless Compound Tabs Engine
Tulis implementasi sistem tab multi-view berbasis compound component di `hands-on/m02/src/components/Tabs/Tabs.tsx`:

```tsx
// hands-on/m02/src/components/Tabs/Tabs.tsx
import React, { createContext, useContext, useState, useCallback, useMemo, ReactNode } from 'react';

interface TabsContextType {
  activeTab: string;
  setActiveTab: (id: string) => void;
  orientation: 'horizontal' | 'vertical';
}

const TabsContext = createContext<TabsContextType | null>(null);

function useTabs() {
  const context = useContext(TabsContext);
  if (!context) {
    throw new Error('Tabs compound sub-components must be wrapped within <TabsRoot>');
  }
  return context;
}

export interface TabsRootProps {
  children: ReactNode;
  defaultValue: string;
  orientation?: 'horizontal' | 'vertical';
  onChange?: (value: string) => void;
}

export function TabsRoot({
  children,
  defaultValue,
  orientation = 'horizontal',
  onChange,
}: TabsRootProps) {
  const [activeTab, setTabInternal] = useState<string>(defaultValue);

  const setActiveTab = useCallback(
    (id: string) => {
      setTabInternal(id);
      onChange?.(id);
    },
    [onChange]
  );

  const value = useMemo(
    () => ({ activeTab, setActiveTab, orientation }),
    [activeTab, setActiveTab, orientation]
  );

  return (
    <TabsContext.Provider value={value}>
      <div
        className={`tabs-container ${
          orientation === 'vertical' ? 'flex flex-row' : 'flex flex-col'
        }`}
      >
        {children}
      </div>
    </TabsContext.Provider>
  );
}

export function TabsList({ children, className = '' }: { children: ReactNode; className?: string }) {
  const { orientation } = useTabs();
  return (
    <div
      role="tablist"
      aria-orientation={orientation}
      className={`flex ${orientation === 'vertical' ? 'flex-col' : 'flex-row'} border-b ${className}`}
    >
      {children}
    </div>
  );
}

export function TabTrigger({
  value,
  children,
  className = '',
}: {
  value: string;
  children: ReactNode;
  className?: string;
}) {
  const { activeTab, setActiveTab } = useTabs();
  const isActive = activeTab === value;

  return (
    <button
      role="tab"
      type="button"
      aria-selected={isActive}
      tabIndex={isActive ? 0 : -1}
      onClick={() => setActiveTab(value)}
      className={`px-4 py-2 font-medium border-b-2 transition-all ${
        isActive
          ? 'border-blue-600 text-blue-600'
          : 'border-transparent text-gray-500 hover:text-gray-700'
      } ${className}`}
    >
      {children}
    </button>
  );
}

export function TabContent({
  value,
  children,
  className = '',
}: {
  value: string;
  children: ReactNode;
  className?: string;
}) {
  const { activeTab } = useTabs();
  if (activeTab !== value) return null;

  return (
    <div role="tabpanel" tabIndex={0} className={`p-4 ${className}`}>
      {children}
    </div>
  );
}
```

### 15. Quiz Evaluasi Pemahaman

#### Bagian 1: Basic (5 Soal)
1. **Apa perbedaan mendasar antara fase Render dan fase Commit pada React Fiber Engine?**
   - *Jawaban*: Fase Render bersifat asinkronus dan dapat diinterupsi (*interruptible*); engine menghitung perbedaan tree dan menyusun work list. Fase Commit bersifat sinkronus dan tidak dapat diinterupsi (*uninterruptible*); engine mengaplikasikan mutasi/efek langsung ke native DOM host.

2. **Mengapa membagi React Context menjadi StateContext dan DispatchContext dapat mencegah re-render cascade yang tidak diinginkan?**
   - *Jawaban*: Karena komponen yang hanya perlu memicu mutasi (dispatch action) hanya mengonsumsi DispatchContext (yang referensi function-nya distabilkan via `useCallback`). Komponen tersebut tidak akan dievaluasi ulang saat nilai data di StateContext berubah.

3. **Apa arti dari property `alternate` pada sebuah objek Fiber node?**
   - *Jawaban*: Pointer `alternate` mereferensikan counterpart dari node tersebut di buffer seberang (menghubungkan node pada pohon `current` yang sedang aktif di layar dengan node pada pohon `workInProgress` yang sedang dikomputasi).

4. **Bagaimana mekanisme dependency tracking pada Vue 3 mendeteksi reaktivitas variabel?**
   - *Jawaban*: Melalui ECMAScript `Proxy` trap `get`. Ketika fungsi render atau `effect` mengeksekusi pembacaan nilai properti, interceptor `get` memicu `track()` untuk mendaftarkan efek aktif ke dalam dependensi map.

5. **Apa fungsi dari atribut accessibility `aria-activedescendant` pada komponen listbox/combobox virtual?**
   - *Jawaban*: Menginformasikan assistive technology (screen reader) elemen anak mana yang sedang berstatus fokus/aktif secara logis, sementara fokus DOM fisik browser tetap dipertahankan pada elemen `<input>`, menghindari overhead manipulasi DOM focus native.

#### Bagian 2: Intermediate (5 Soal)
6. **Pada React Scheduler, bagaimana prioritas `Lane` menyelesaikan konflik antara user input (ketikan) dan background fetch response?**
   - *Jawaban*: User input dialokasikan ke `SyncLane` atau `InputContinuousLane` dengan time budget mendesak. Jika Fiber work loop sedang memproses background response (`DefaultLane`), work loop akan diinterupsi (*yield/abort*), me-reset pointer `workInProgress`, memprioritaskan dan me-render `SyncLane` hingga selesai ke commit phase, baru kemudian me-restart pemrosesan `DefaultLane`.

7. **Sebutkan risiko performa dari penggunaan teknik Inline Function Props pada compound child component (`<List item={(data) => <Item {...data} />} />`) dan bagaimana memitigasinya!**
   - *Jawaban*: Inline arrow function menciptakan referensi fungsi baru pada setiap render parent, menyebabkan kegagalan memoization pada child component (`React.memo` menganggap prop berubah). Mitigasinya adalah mengekstrak fungsi render ke callback yang distabilkan (`useCallback`) atau merestrukturisasinya menjadi Compound Children konvensional.

8. **Bagaimana Svelte mencapai reaktivitas tanpa alokasi memori VDOM atau overhead Dependency Tracking Map seperti Proxy?**
   - *Jawaban*: Melalui AST compilation. Kompiler Svelte menganalisis statement assignment (`count = count + 1`), lalu menginjeksikan fungsi invalidasi runtime imperatif (`$$invalidate`) secara tepat pada target node DOM yang terikat pada variabel tersebut saat build time.

9. **Apa itu Layout Thrashing (Reflow Waterfall) dalam konteks update UI siklikal pada custom component lifecycle?**
   - *Jawaban*: Kondisi buruk di mana JavaScript secara berulang-ulang membaca geometri DOM (misal `node.offsetHeight`) segera setelah memutasi style DOM (misal `node.style.height = ...`). Hal ini memaksa browser mengeksekusi komputasi reflow/layout sinkronus secara berulang dalam satu frame loop.

10. **Mengapa penutupan closure lama (*stale closures*) sering terjadi saat mengimplementasikan custom hooks pada arsitektur komponen compound?**
    - *Jawaban*: Terjadi ketika sebuah fungsi asynchronous atau callback effect meng-capture variabel state dari scope render sebelumnya, namun dependency array hook (`useEffect`, `useCallback`) tidak mencantumkan variabel tersebut secara benar, sehingga callback terus merujuk pada referensi nilai kadaluarsa.

#### Bagian 3: Skenario Kasus Produksi (3 Skenario)
11. **Skenario Kasus A**:
    Aplikasi Enterprise E-Commerce meluncurkan fitur Multi-Select Filter pada katalog produk. Pengguna melaporkan bahwa saat memilih opsi filter dengan cepat, checkbox terasa "macet" (freezing) selama ~300ms, dan urutan highlight fokus meloncat secara acak. 12. **Skenario Kasus B**:
    Sebuah Micro-Frontend dashboard finansial memuat komponen chart analytics dari remote federated module (`Module Federation`). Setelah berpindah halaman bolak-balik antara dashboard dan settings sebanyak 10 kali, tab Chrome crash dengan status `Out of Memory`.

      2. Komponen chart di-unmount dari React Fiber tree, namun referensi global listener mencegah JavaScript Garbage Collector mereclaim memori Fiber subtree dan DOM node terkait (*Retained Size* membesar).
      3. **Langkah Diagnostik**: Rekam *Allocation Instrumentation on Timeline* pada Chrome DevTools Memory Tab. Navigasikan bolak-balik antar halaman. Filter objek berdasarkan nama modul federated. Cari objek `Detached FiberNode`. Perbaiki dengan menyediakan cleanup callback mutlak pada `useEffect` unmount phase untuk memutus listener, menghentikan observer (`observer.disconnect()`), dan membuang referensi native instance chart.

13. **Skenario Kasus C**:
    Design System Enterprise Anda mewajibkan implementasi Form Validation Engine terpadu. Developer junior membangun komponen `<Form>` compound di mana setiap `<Field>` mendaftarkan dirinya ke root melalui `useEffect` imperatif. Saat form kompleks dengan 150 fields dibuka, browser mengalami *Cascading Render Loops* (me-render ulang root form sebanyak 150 kali berturut-turut pada inisialisasi).
    *Pertanyaan*: Mengapa cascading render ini terjadi dan bagaimana pola arsitektur refaktorisasi terbaiknya?
    - *Solusi Analitis*:

      2. **Arsitektur Refaktorisasi**: Pindahkan registration bus ke **Mutable Form Store** menggunakan mutable collection (`new Map()`) di level Context tanpa memicu React state mutation. Gunakan pola `useSyncExternalStore` di mana field hanya subscribe ke slice state miliknya sendiri, dan inisialisasi metadata form dilakukan secara sinkronus atau decoupled dari render cycle React.

### 16. Summary

- **Fiber Reconciler** mengabstraksikan UI ke dalam bentuk representasi linked list ganda (*workInProgress* vs *current*) yang memungkinkan prioritas komputasi time-slicing dan concurrency.
- **Headless Compound Component Architecture** memberikan derajat decoupling tertinggi antara business logic/state machine dengan UI presentation, mengeliminasi prop-explosion dan meningkatkan skalabilitas codebase enterprise.
- **Granular Split Context** merupakan mekanisme fundamental dalam React untuk memotong jalur propagasi re-render antara data produsen aktif dan consumer interaksi statis.
- Menguasai Framework Internals (apakah itu Fiber lanes React, Reactive dependency graph Vue, atau Compilation AST Svelte) adalah kapabilitas pembeda antara pengembang yang sekadar "merakit UI" dengan Senior Frontend Architect yang mampu mendesain sistem berskala masif dengan performa stabil, zero memory leaks, dan arsitektur kelas enterprise.
